# canonical source, which is what makes the arms comparable:
#   piC  <- ocean_wide/evaluator-config-piC-200yr-var.yaml on
#           exper/2026-08-25-variance-diagnosis (blob aee8da6aa) -- the very
#           config the deterministic ocean_wide_ohc_clip-ft baseline ran as

#           the shared config every arm in the family has run.

# Why the piC "-var" flavour and not the shared piC-ic0151-200yr config: it is
# the same evaluation (icx1-1deg-picontrol-200yr -- one IC at 0151-01-06,
# 14598 steps, same stores), differing only in what is written to disk, so the
# wandb metrics are directly comparable either way. It wins on two other
# counts. It is what the baseline actually ran, so this is a like-for-like
# match rather than a near-match. And it writes sst_monthly + ohc_monthly +
# vo_monthly_rapid at ~4.5 GiB per run instead of the shared config's
# save_monthly_files: true, which writes every channel at ~76 GiB per run --
# while still producing the sst_monthly_{predictions,target}.nc pair that
# band_variance_sst.py reads, so this task's pre-registered coast-distance and
# boundary-current criterion can be computed later without a second 200-year
# wave.
#

# the baseline's own 1pct wave did (experiments/2026-08-26-ohc-clip-ft-1pct-130yr):
# nothing has ever read those files and the comparison runs off the wandb
# per-step and time-mean series.

# ~65 minutes and a 1h guarantee expired minutes before the last step, losing
