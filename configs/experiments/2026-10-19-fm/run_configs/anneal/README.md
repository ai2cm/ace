# Anneal sweep (2026-10-19 nc-sfno balanced parents)

30 fine-tuning runs: 6 arms x 5 seeds, each starting from the last EMA
checkpoint (`training_checkpoints/ema_ckpt_0150.tar`) of one finished
`ace2-fm-nc-sfno-fm-a2-cond-era5-c96-piC-1pct-cm4-xshield-balanced-s{k}-mask{on,off}`
parent. Generated by `../../create_anneal_jobs.py`, submitted by
`../../submit_anneal_jobs.py` via `../../run-ace-anneal.sh`.

- Job / wandb run name: `{parent job}-anneal-a{N}`; config:
  `{parent config stem}-anneal-a{N}.yaml` (header lines hold the parent job,
  parent result dataset and Beaker description).
- wandb: entity `ai2cm`, project `FM`, group `ace2-fm-anneal-2026-10-19`.
- Beaker: workspace `ai2/ace`, clusters jupiter/titan/saturn, priority normal,
  2 GPUs, 200 GiB shared memory (same as the parents).

All arms, relative to the parent config:

- `stepper_training.parameter_init.weights_path: /parent_ckpt.tar`, mounted
  from the parent's result dataset. Loads stepper (EMA) weights only: fresh
  optimizer, EMA re-initialised from the loaded weights, epoch counter 0, no
  `resume_results`.
- `max_epochs: 20`; `optimization.scheduler`: `LinearLR`, start_factor 1.0,
  end_factor 0.0, total_iters 20, stepped per epoch. Epoch e trains at
  `1e-4 * (1 - (e-1)/20)`: 1e-4 in epoch 1, 5e-6 in epoch 20 (0 is reached
  only after the last epoch).
- `input_dropout.default.max_masked_vars: 0` (masking off);
  `include_channel_mask_inputs: true` kept so input channels match the parent.
- `ema_checkpoint_save_epochs: {start: 16, step: 1}`: saves
  `training_checkpoints/ema_ckpt_0016.tar` ... `ema_ckpt_0020.tar` (1-based
  epoch numbers). `best_inference_ckpt.tar` (EMA weights, lowest
  `aimip_checkpoint_era5` time-mean RMSE) is also saved.
- `inference`: only `aimip_checkpoint_era5` (weight 1) and
  `aimip_checkpoint_c96` (weight 0), every epoch, 8 ICs x 1825 days, unchanged
  from the parent.
- Everything else (data, normalization, model, batch size 8, n_ensemble 2,
  loss, validation, seed) is the parent's.

## Deviations from the requested spec

1. **No inline +4 K SST entry.** `InferenceDataLoaderConfig.perturbations`
   exists, but inline inference (`InlineInferenceConfig.get_inference_data`)
   does not pass the surface-temperature / ocean-fraction names to
   `get_inference_data`, so `InferenceDataset` raises "SST perturbations
   require an ocean configuration" at runtime. Fixing it needs an `fme/`
   change. Dataset `overwrite` has only `constant` / `multiply_scalar`, so no
   uniform +4 K is possible there either.
2. **a4 multi-step:** stochastic lengths are supported on this branch
   (`n_forward_steps.outcomes`). ACE2.2's 1/2/4/12/20 (p .6/.2/.1/.05/.05),
   capped at 4 steps with the >4 mass moved to 4: 1/2/4 at .6/.2/.2.
   `optimize_last_step_only: true`; earlier steps run without gradient. Batch
   size unchanged. Validation evaluates all 4 steps for a4, so a4's `val/`
   loss is not comparable with the other arms (checkpoint selection uses
   inline inference, unaffected).
3. a3's zero weights are accepted (weight 0 = label never drawn); the other
   sources stay in the concat. Epoch size stays the full dataset size, so
   ERA5 samples repeat within an a3 epoch.
4. Label weights are the spec's rounded values (normalized by their sum).
5. Each run keeps its parent's seed.

## Inline log keys

Inline entries log under their entry name (no `inference/` prefix). Confirmed in the a1 smoke (wandb `ai2cm/FM` run `c00medj9`):

- Channel-mean time-mean RMSE (normalized; checkpoint selection uses the era5 one, weight 1):
  `aimip_checkpoint_era5/time_mean_norm/rmse/channel_mean`,
  `aimip_checkpoint_c96/time_mean_norm/rmse/channel_mean`
- Global-mean drift (#1617, on by default; both entries are 1825 days > 730):
  `aimip_checkpoint_era5/global_mean_drift/max_abs_t`,
  `aimip_checkpoint_era5/global_mean_drift/slope/<var>` (per year),
  `aimip_checkpoint_era5/global_mean_drift/t/<var>`, and the same under
  `aimip_checkpoint_c96/`.
- +4 K ΔTMP2m: not logged (no +4 K entry, see deviation 1).
- Learning rate: `lr`.
